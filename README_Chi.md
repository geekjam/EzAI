# 简单易用 AI 工作流（.ai）

一套把 AI 协作过程拆分成**可编辑 Markdown 计划文件**的工作流。每个阶段对应一个 `.md` 计划文件，在你的 AI 编程助手（如 Claude Code 或 Codex）里直接点名执行哪个计划，AI 就按该文件的步骤推进。

> 通过可编辑的 Markdown 计划文件，把项目定义、任务规划和任务执行变成可预测的 AI 协作流程。

> English version: [README.md](README.md).

---

## 快速开始

1. 把 `.ai` 文件夹复制到你的项目根目录，不需要任何配置。
2. 对 AI 编程助手说：**`执行 .ai/Define 计划`**
   AI 会开始定义/更新项目，生成 `README.md`、`FileTree.md`、`Standards.md`。

就这样 —— 计划文件本身就是给 AI 看的指令。AI 会打开 `.ai/X.md` 并按里面写的步骤走。

---

## 工作流总览

把一次开发拆成三个阶段，每个阶段一个计划文件：

| 阶段 | 计划文件 | 做什么 | 产出 |
|---|---|---|---|
| 1. 定义 | `.ai/Define.md` | 明确项目目标、技术栈、目录结构、规范 | `README.md`、`FileTree.md`、`Standards.md` |
| 2. 规划 | `.ai/Plan.md` | 把要做的事拆成步骤、逐项问清楚 | `.ai/task/NNN.<english-task-name>.md` 任务清单 |
| 3. 执行 | `.ai/Run.md` | 按任务清单一步步做，做完回写状态 | 代码 + 更新后的任务清单 |

流程：**Define → Plan → Run →（如有偏差）回到 Define 同步文档**。

`Define` 始终会生成 `FileTree.md` 与 `Standards.md`。如果项目包含后端接口，计划还会询问是否生成或更新 `API.md`。

## Make Commit（可选）

在 `Run` 之后，或任何已经准备好提交的时刻，执行：

**`执行 .ai/Commit 计划`**

AI 会检查当前目录是否为 Git 仓库，默认基于最近修改和新增但尚未提交的文件生成提交，并在存在 `Standards.md` 提交规范时遵循该规范。随后，AI 会询问是仅提交不推送，还是提交并推送。

## 目录结构

```
项目根/
└── .ai/
    ├── README.md          # 本工作流说明文件
    ├── Define.md          # 阶段 1：定义项目计划
    ├── Plan.md            # 阶段 2：规划任务计划
    ├── Run.md             # 阶段 3：执行任务计划
    ├── Commit.md          # 可选：生成 Git 提交计划
    └── task/              # 任务计划文件存放处
        ├── 001.initialize-project.md
        └── 002.user-login-module.md
```

## 编程语言与框架

本项目**不包含任何运行时代码**，核心资产是 Markdown 计划文件，由能够读取本地文件并按其中指令行事的 AI 编程助手（如 Claude Code 或 Codex）执行。

不需要安装任何构建工具、包管理器或运行时依赖。

---

## 功能特性

1. **阶段化计划文件** —— `Define` / `Plan` / `Run` 把一次开发拆成三个阶段；AI 在动手前会逐项问清楚。
2. **计划即指令** —— 用自然语言 `执行 .ai/Define 计划` 即可触发对应阶段，无需脚本或配置文件。
3. **任务清单追踪** —— `.ai/task/` 下用 `[ ]` / `[~]` / `[x]` 标记状态，文件名采用固定三位、左侧补零的序号格式，例如 `001.initialize-project.md`，确保按字符串排序时仍保持任务顺序。
4. **文档回写机制** —— `Run` 收尾会再跑一次 `Define`，把架构/框架变动同步回 `README` / `FileTree` / `Standards`。
5. **零运行时依赖** —— 全部是 Markdown，复制即用，修改计划行为只改 `.md` 文件即可。
6. **可选 Git 提交助手** —— `Commit` 读取最近修改和新增的未提交文件，存在 `Standards.md` 提交规范时遵循该规范，并询问是否推送。

## 前置条件

- 一个能读取本地文件并按 Markdown 指令执行的 AI 编程助手（Claude Code 或 Codex 都可以）。
- 了解 Markdown 基本语法。
- 不需要 Node、Python、.NET 或任何其他运行时环境。

## 适用场景

- 从零开始用 AI 协作开发一个新项目；
- 给已有项目引入结构化的 AI 协作流程；
- 团队多人协作时统一 AI 协作指令与任务跟踪格式。

---

## 任务清单状态约定

任务计划 `.md` 文件里每一项前用状态标记：

| 标记 | 含义 |
|---|---|
| `[ ]` | 未开始 |
| `[~]` | 进行中 |
| `[x]` | 已完成 |

文件命名：`NNN.<english-task-name>.md`，其中 `NNN` 是固定三位、左侧补零的序号，例如 `001.initialize-project.md`、`002.user-login-module.md`。固定宽度可确保文件按字符串排序时与数字顺序一致。

---

## 怎么改

这套工作流没有任何代码，全是 Markdown。改计划行为就直接编辑 `.ai/` 下的三个 `.md` 文件：

- 想改**定义**问什么 → 编辑 `Define.md`
- 想改**规划**的方式 → 编辑 `Plan.md`
- 想改**执行**的流程 → 编辑 `Run.md`

任务计划模板在 `Plan.md` 里描述，改那里的命名/状态约定即可影响所有新生成的任务文件。

---

## 设计要点

1. **每个阶段一个文件** —— 职责单一，看一眼就知道这步干什么。
2. **计划文件即指令** —— 不需要脚本、不需要配置，AI 直接读 Markdown 执行。
3. **强制提问对齐** —— `Define` 和 `Plan` 都要求 AI 一问一答问到清楚再动手，避免理解偏差。
4. **执行完回写文档** —— `Run` 收尾时会跑一次 `Define`，确保文档和代码不脱节。
5. **不碰代码直到该碰** —— 前两个阶段明确禁止改代码，先把项目和任务想清楚。
